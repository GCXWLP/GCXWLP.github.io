普通UDF提权

UDF（user defind function）用户自定义函数，我们可以添加新的函数，扩充Mysql的功能，然后去调用，执行系统命令

udf文件后缀在windows与linux系统下分别为dll与so，即动态链接库文件，由C、C++编写(和我在RCE进阶的那章中写的手搓进阶姿势有点类似,但是那个是php文件编译成so文件)

而我们的提权，就是为了达成mysql权限 —> 操作系统权限的目的

前置知识:来讲讲NTFS ADS流

在 NTFS（New Technology File System）中，每个文件或目录不仅仅只有一个“主数据流”（primary data stream），还可以有若干个“备用数据流”（Alternate Data Streams，简称 ADS）

再来分析国光师傅的payload

众所周知，我们在windows中可以通过下列的方式来写入与读取ADS内容

细看payload，后续为何使用了两个::
第一个冒号

就是上述的写入ADS流
例如example.txt:secret 就是对 example.txt 文件中的名为 secret 的 ADS 进行读写
第二个冒号
用来指定 NTFS 自身的“元数据属性”（MFT attribute），这里的 $INDEX_ALLOCATION 就是 NTFS 用来存储目录索引的内部属性名。

写 plugin::$INDEX_ALLOCATION 时，等同于：
流名称为空（你没有给这个 ADS 取用户级别的名字），
直接指定要写入的是该文件／目录的 $INDEX_ALLOCATION 元数据属性

所以双冒号其实就是ADS语法冒号+内部属性字段的冒号

但是据说用NTFS ADS流创建的成功率很低，现在似乎mysql也去除了这个功能了

手工提权

MOF提权的原理是 C:/Windows/system32/wbem/mof/ 目录下的 mof 文件每 隔一段时间（几秒钟左右）都会被系统执行，因为这个 MOF 里面有一部分是 VBS 脚本，所以可以利用这个 VBS 脚本来调用 CMD 来执行系统命令，如果 MySQL 有权限操作 mof 目录的话，就可以来执行任意命令了(想起之前自己写vbs脚本来发送消息轰炸的日子)
